# 规则模块：FACT 事实核销原则 (Fact Verification Protocol)

> 模块状态：[核心必选]  
> 目标：根除大模型在任务执行中的虚假承诺与幻觉，确保个人系统中的每一条待办都是真实可信的。

---

## 核心机制定义

1. **未经验证不打勾**：
   - 任务清单中凡是标有 `[ ]` 的待办，只有在 Agent 实际调用终端执行通过、文件实际生成成功、或用户亲身实测确认后，方可改为 `[x]`。

2. **`[FACT]` 标记契约**：
   - 当任务核销时，在条目末尾显式附加 `[FACT]` 以及验证日期，例如：
     ```markdown
     - [x] 完成本地嵌入向量模型 Ollama-nomic-embed 部署与维度测试 [FACT] (2026-10-18)
     ```
   - `[FACT]` 代表可追溯、可复现、经验证的确定性知识，与未经证实的“猜测”物理隔离。

3. **报错直面机制**：
   - 若执行报错或卡死，保留原待办 `[ ]`，输出失败切片与定位推断，等待指令或切换备选路径，禁止掩盖问题。
